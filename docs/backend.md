# 後端（Google Apps Script）
[← 回總覽](../README.md)

各頁面中的 `SCRIPT_URL` 指向同一個 Google Apps Script 網頁應用程式，後端程式碼是本機檔案 `local/Code.gs`（不在儲存庫中）。資料存在 Google 雲端硬碟的 JSON 檔，並同步一份到 Google 試算表方便老師查看。

## 初次設定或更新後端

1. 開啟 Apps Script 專案，把 `local/Code.gs` 整份複製，貼進 `程式碼.gs` 覆蓋，按 Ctrl+S。
2. 到「專案設定 → 指令碼屬性」，確認 `CE_API_KEY` 已設定，且和網頁中的 `API_KEY` 完全一致。
3. 在上方函式選單選 **`一鍵設定`**，按「執行」一次。它會一次完成：
   - 每 15 分鐘自動抓真實行情
   - 每 5 分鐘自動把交易同步到試算表
   - 每天凌晨 2 點自動備份並存「每日快照」，每週一凌晨 3 點自動產生週報
   - 立刻抓第一筆行情，並存下今天的快照
4. 「部署」→「管理部署作業」→ 編輯 → 版本選「新版本」→ 部署。

之後如果只是修改程式碼，只要重做第 1 步和第 4 步。`一鍵設定` 重複執行也安全。

## 試算表同步的時間差

學生在投資市場買賣時，系統只更新資料檔，不會當下寫入試算表，所以交易才會快。試算表的「目前總覽」和「歷史紀錄」最多會晚 5 分鐘更新。學生看到的分數和持倉不受影響。

## 老師工具（函式選單中直接執行）

| 函式 | 用途 |
| --- | --- |
| `一鍵設定` | 初次設定，見上方 |
| `手動更新行情` | 立刻抓一次真實行情，不用等 15 分鐘 |
| `diagnoseDataFiles` | 檢查雲端硬碟上有幾份資料檔，有重複時要刪掉多餘的 |
| `rebuildOverview` | 用目前資料重新產生試算表的「目前總覽」 |
| `設定每週摘要信` / `寄出摘要信測試` | 每週一 07:00 自動把「需關心／留意」和「值得肯定」名單寄到老師信箱，並標出哪些是這週新增的。收件人預設是 Apps Script 專案擁有者，要改請在指令碼屬性新增 `CE_DIGEST_EMAIL`。第一次執行會跳出寄信授權。先跑「寄出摘要信測試」看信的長相（不影響之後的「新增」標記）。判斷規則與教師後台相同，改規則時 `local/Code.gs` 的 `judgeStudent_` 和 `local/teacher.html` 的 `judge` 要一起改 |
| `重建月考紀錄` | 「月考紀錄」分頁由歷史紀錄整理而來，第一次部署會自動建好；計分板登記與後台批次登記都會進來，「復原」月考會沖掉那一筆。有異動時可用它整份重算 |
| `寫入今日狀態紀錄` | 立刻寫入今天的「狀態紀錄」（每天 02:00 也會自動寫，同一天不會重複） |
| `更新儀表板` | 立刻重新產生試算表的「儀表板」與「學生一覽」（每天 02:00 也會自動更新）。第一次部署後請先執行一次 |
| `更新欄位說明` | 重新寫入試算表的「欄位說明」分頁（說明每個分頁與欄位的意思；第一次同步會自動建立，這個函式會覆蓋它的內容） |
| `重算累計加扣分` | 「目前總覽」的累計加分／扣分只算老師給的行為加扣分（答題、習作、助人、忘物、月考…），不含投資、借貸、闖關，並已沖掉「復原」。算法有改過時，用歷史紀錄整份重算一次 |
| `cleanupSnapshot` | 清掉每日快照的重複列和測試列 |
| `listBackups` / `restoreFromBackup` | 查看每日備份，或還原成某一天的備份 |
| `補齊學生ID預覽` / `補齊學生ID` | 歷史紀錄、每日快照、週報、請假紀錄新增了「學生ID」欄，學生改名或同名時才不會對錯人。舊資料要執行一次來補：先跑「預覽」看會補幾列，再跑正式版。只寫ID那一欄，可重複執行。**請在改任何學生名字之前先做** |

## 常見問題

- **函式選單找不到某個函式**：名稱結尾是底線 `_` 的函式不會顯示，這是正常的。要執行的都是上表列出的函式。
- **買賣仍然很慢**：確認已執行過 `一鍵設定`，且部署的是「新版本」。
- **行情顯示「資料較舊」**：執行 `手動更新行情`，並檢查觸發器是否存在（Apps Script 左側時鐘圖示）。
