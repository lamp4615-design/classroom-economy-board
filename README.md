# 班級經濟

課堂用的班級經濟系統：老師管理計分，學生可以投資、闖關賺取班級幣。純前端靜態網頁，資料由 Google Apps Script 後端存取。

## 頁面

| 檔案 | 說明 | 使用者 |
| --- | --- | --- |
| `index.html` | 入口頁，連到下方三個功能 | 全部 |
| `scoreboard.html` | 班級計分板，管理學生資料與投資設定 | 老師 |
| `invest.html` | 投資市場，K 線、均線、成交量、多標的買賣 | 學生 |
| `game.html` | 闖關挑戰 | 學生 |

## 教師後台（只放本機）

`teacher.html`（教師後台）和 `Code.patched.gs`（後端程式碼）含有學生資料入口與後端細節，已列入 `.gitignore`，**不會推上 GitHub**，只存在老師自己的電腦。這兩個檔案請自行備份（例如複製到雲端硬碟）。

用瀏覽器直接開啟本機的 `teacher.html`，輸入教師密碼即可。資料來自試算表的「歷史紀錄」「每日快照」「月考紀錄」「狀態紀錄」「老師備註」。除了「登記月考成績」和「老師備註」會寫入之外，其餘都只讀取。

畫面由上到下是：

- **班級概況**：最上面一句話先講結論（幾位需關心、幾位留意、幾位值得肯定），下面是數字卡：需關心／留意人數、值得肯定人數、本週有參與的人數、平均參與次數、忘物總次數（這三項會和上週比，▲▼ 標示變好或變差）、月考待登記人數、有投資交易的人數。**每張數字卡都可以點**，會捲到對應的區塊。
- **需要關心**：「需關心」排在「留意」前面，名單超過 6 位時先顯示前 6 位（「已談過」的排在還沒處理的後面），可按「顯示其餘」展開；寫過備註的學生旁會有 📝。條列學生與具體原因，例如「已連續兩週沒有任何正向參與紀錄」「參與次數比前 3 週明顯減少」「近 7 天忘物 3 次以上」「借款應還不低於現有分數」「月考未達目標」「身價淨值近 7 天下降 10% 以上」。
- **值得肯定**：參與明顯增加、連續 4 週都有參與、樂於幫助同學、投資獲利、月考達標。
- **輔導配對**：事先登記「誰輔導誰」，期末月考登記完，後台會算出被輔導者的進步分數（最新月考實際分數 − 登記配對時的上一次月考）和預計加分，加分規則沿用計分板「輔導」的設定（進步超過門檻：基本分＋超出分數×每分加分）。按「結算」或「一鍵結算」才會發分，發分寫法和計分板的輔導相同（歷史紀錄歸在「輔導加分」）；進步沒超過門檻的也會結算但不發分。每組配對只能結算一次，結算前會列出明細讓你確認。**防重複發分**：如果輔導者在配對建立之後，已經用計分板的「輔導」按鈕手動領過同一位同學的加分（已扣掉「復原」），表格會標出「⚠ 已手動領過 +N 分」，結算時系統不會直接發，要你明確確認才發。有可結算的配對時，這張卡會自動展開，上方數字卡也會顯示可結算組數。
- **判讀設定**（頁面最下方，預設收合）：可以調整「需關心／留意」的門檻——忘物幾次、身價淨值降幾 %、參與減少到前 3 週平均的幾 %、長期偏低的比例；以及**暫停判讀到某一天**（放假、停課、段考週用，期間不判斷參與相關的提醒，過了自動恢復）。設定存在試算表的「後台設定」分頁，教師後台、每日狀態紀錄、每週摘要信共用。身價淨值會受行情影響，覺得太吵可以調高或設 0 關閉。
- **近 8 週參與**：上半是全班每週「每人平均」的正向參與（藍）與忘物（紅）折線；下半是熱力圖，每列一位學生、每格一週（7 天滾動區間，不是週一到週日），顏色越深參與越多，格子裡一定有數字，右上角紅色小三角表示該週有忘物。排序與篩選和「全班一覽」相同，點學生看個人歷程。試算表紀錄還不足的週會畫成斜線格「還沒有資料」，不會誤當成 0 次；資料不足一整週的格子用虛線框、折線用空心點標示。如果全班同時明顯偏低（多半是放假、段考週或少記錄），上方會顯示提示，而且**不會逐人提醒「沒有參與／參與減少」**。
- **這次月考**：平常只顯示一行摘要；要看目標分布、達標率或登記成績時才展開。
- **全班一覽**：預設只顯示重點欄位（姓名、狀態、近 8 週參與小圖、正向參與、忘物、最近參與），姓名欄固定在左邊；按「顯示全部欄位」可看答題／習作／助人／淨值變化／投資損益等。可用「全部／需關心／留意／良好」篩選；點欄位標題排序，可切換近 7 天、近 30 天、全部，也能匯出 CSV（匯出一律包含全部欄位）。
- **個人歷程**（點學生）：自動產生的一段摘要、每週參與長條圖、分數與身價淨值曲線、各項紀錄次數、投資持倉、月考目標狀況與歷次月考（目標／實際／差距）、老師備註。可以「列印 / 存成 PDF」給親師座談使用（注意：備註欄也會一起印出來）。

「正向參與」＝答題、習作、助人、輔導的次數。關心與肯定名單固定用「近 7 天 vs 前 3 週」判斷，不受時間範圍影響。這些提示是幫老師快速找人的線索，**不是對孩子的評價**：沒有紀錄不代表沒有學習，請搭配課堂觀察。試算表紀錄累積不到 14 天時，畫面會提醒趨勢判讀要保守。

**老師備註**會自動存到試算表的「老師備註」分頁（每位學生一列），換電腦、清瀏覽器都不會不見。兩台裝置同時改同一位學生時，後存的人會看到提示，可以選「載入最新版」或「用我的覆蓋」，不會默默蓋掉。舊版存在瀏覽器裡的備註，第一次打開新版時會自動搬到試算表。請在後台修改備註，不要直接改試算表那個分頁。

**處理狀態**：在學生的個人歷程裡可以標記「📌 追蹤中」「💬 已談過」「🔕 暫不提醒 7／14／30 天」，和備註存在同一列。「暫不提醒」到期前，這位學生不會出現在關心名單、數字卡計數與每週摘要信（改列在名單下方一行，點名字還是看得到）；「已談過」「追蹤中」只是標籤，仍會顯示。

**請假與全班基準線**：「請假紀錄」分頁（計分板登記的請假）現在會用在判讀上：近 7 天有請假的學生，不會被列為「沒有參與／參與減少」（近 2 週有請假則不列「連續兩週沒有參與」），個人歷程會寫明「已排除的提醒」。另外加了**「長期偏低」**規則：近 4 週正向參與低於全班中位數的 25%（可調）時列為「留意」，用來抓每週都只有一點點、所以不會觸發其他規則的安靜孩子（班上至少 5 人、紀錄滿 4 週、全班中位數至少 4 次才判斷）。

**試算表視覺化**：試算表裡有兩個由系統每天 02:00 整份重寫的分頁，不用開後台就能看——**「儀表板」**：各班摘要（參與率、平均參與、忘物、需關心／留意／良好人數）、各班狀態分布（堆疊直條圖）、每週每人平均參與與忘物（折線圖）、月考達標率（直條圖）；**「學生一覽」**：每位學生一列，狀態顏色、提醒原因、處理狀態、近 8 週參與（色階熱力格，灰底＝還沒有那週的資料）、趨勢小圖（SPARKLINE）、淨值趨勢小圖、最近月考；表頭與前 3 欄凍結，可篩選。判讀規則與設定和後台完全相同；TEST 測試班不會出現。請勿在這兩個分頁手動修改（下次更新會被覆蓋），想自己排版請複製到新分頁。

**狀態追蹤**：每天 02:00 系統會把每位學生當天是「需關心／留意／良好」記進「狀態紀錄」分頁，後台據此在名單上標出「🆕 新增」或「持續 N 天」，並列出「近期已改善」（近 14 天進過名單、現在回到良好）。剛啟用時還沒有紀錄，要先執行一次 `寫入今日狀態紀錄`，之後逐日累積。

首次使用前要設定教師密碼：Apps Script →「專案設定 → 指令碼屬性」→ 新增 `CE_TEACHER_PIN`，值填你要的密碼。後端更新後需重新部署「新版本」。密碼連續輸錯 5 次會鎖定 10 分鐘。

注意事項：
- 密碼只能擋一般人，不是銀行等級的保護。學生姓名與成績屬於敏感資料，建議不要公開這個網頁的網址。
- 試算表的資料最多比實際晚 5 分鐘。
- 學生按「復原」時，計分板會多寫一筆相反的紀錄、原紀錄不會刪。後台與週報會把「復原」沖掉原本那一筆（次數 -1），所以次數會和實際一致。

## 學生端（大螢幕模式）的限制

- **沒有「輔導」按鈕**：進步分數由學生自己填、沒有驗證，也會和後台的輔導配對重複發分，所以拿掉了。輔導加分只由老師在教師後台的「輔導配對」結算，進步分數由月考紀錄自動計算。計分板（老師端）的學生列也沒有「輔導」按鈕了。
- **螢幕數字鍵盤**：教室大螢幕常沒有實體鍵盤，系統也不一定會自動跳出觸控鍵盤，所以大螢幕模式自己畫了一個數字鍵盤。點到數字欄位（月考目標、月考成績、借入、投資、還款、座號學號等）就會出現；第一次按數字會取代原本的內容（目標預設 80，直接按 9、0 就是 90），小數點只能有一個，最多 8 個字元，按「完成」收起。離開大螢幕模式用的 PIN 欄位也有，實體鍵盤照樣能用。只有大螢幕模式才有，老師端不受影響。請假的「備註」是文字欄位，仍需要系統或實體鍵盤。
- **「月考成績」登記過就不能再送出**：這次月考成績不論是學生自己或老師在後台登記過，按鈕都會變成「已登記」，避免重複加分。老師端的計分板仍可再送一次（視窗會警告）。

## 後端（Google Apps Script）

各頁面中的 `SCRIPT_URL` 指向同一個 Google Apps Script 網頁應用程式，後端程式碼是本機檔案 `Code.patched.gs`（不在儲存庫中）。資料存在 Google 雲端硬碟的 JSON 檔，並同步一份到 Google 試算表方便老師查看。

### 初次設定或更新後端

1. 開啟 Apps Script 專案，把 `Code.patched.gs` 整份複製，貼進 `程式碼.gs` 覆蓋，按 Ctrl+S。
2. 到「專案設定 → 指令碼屬性」，確認 `CE_API_KEY` 已設定，且和網頁中的 `API_KEY` 完全一致。
3. 在上方函式選單選 **`一鍵設定`**，按「執行」一次。它會一次完成：
   - 每 15 分鐘自動抓真實行情
   - 每 5 分鐘自動把交易同步到試算表
   - 每天凌晨 2 點自動備份並存「每日快照」，每週一凌晨 3 點自動產生週報
   - 立刻抓第一筆行情，並存下今天的快照
4. 「部署」→「管理部署作業」→ 編輯 → 版本選「新版本」→ 部署。

之後如果只是修改程式碼，只要重做第 1 步和第 4 步。`一鍵設定` 重複執行也安全。

### 試算表同步的時間差

學生在投資市場買賣時，系統只更新資料檔，不會當下寫入試算表，所以交易才會快。試算表的「目前總覽」和「歷史紀錄」最多會晚 5 分鐘更新。學生看到的分數和持倉不受影響。

### 常見問題

- **函式選單找不到某個函式**：名稱結尾是底線 `_` 的函式不會顯示，這是正常的。要執行的都是上表列出的函式。
- **買賣仍然很慢**：確認已執行過 `一鍵設定`，且部署的是「新版本」。
- **行情顯示「資料較舊」**：執行 `手動更新行情`，並檢查觸發器是否存在（Apps Script 左側時鐘圖示）。
